# N=3 主窗口时间诊断

本说明只读核对本目录 run_index.csv 中的 12 条记录，时间分布来自 packet_log.csv，主窗口时长和状态来自原 summary.json；不代替独立 raw CRC 审计。原始数据、PASS/CHECK 状态和 Repeat 编号均不修改。

## 统计保留规则

四个组合各录制一个 batch、三个连续时间窗口，每段约 40 s，前 10 s 预留。有效性能均值仅使用完整性 PASS 的主窗口，样本 SD 以段为单位计算，不采用帧率阈值筛选。

| 组合 | 有效 n / 已录 n | 主窗口 MUL1 包率 / Hz | USB 完整包数据率 / Mbit/s |
|---|---:|---:|---:|
| M0_M1_M2 | 2 / 3 | 200.131100 ± 0.000728 | 5.078527 ± 0.000018 |
| M0_M1_M3 | 3 / 3 | 199.766908 ± 0.556959 | 5.069285 ± 0.014133 |
| M0_M2_M3 | 3 / 3 | 200.165942 ± 0.036616 | 5.079411 ± 0.000929 |
| M1_M2_M3 | 3 / 3 | 200.218529 ± 0.040178 | 5.080745 ± 0.001020 |

M012 Repeat 1（20260907_000133_670681）主窗口为 CHECK，不能计入完整性通过记录的性能均值；原始数据仍保留并计入可靠性评估。M012 全部三条的诊断值为 200.091843 ± 0.067998 Hz、5.077531 ± 0.001726 Mbit/s，n=3。其余三组保留全部重复，包括较低帧率；不选取较快两条重算均值。

## M013 Repeat 3：低帧率集中于末段

记录 20260907_001505_375008 的主窗口包含 5974 个有效 MUL1，时长 30.001432 s，包率 199.123828 Hz，完整包数据率 5.052966 Mbit/s。相对同组前两次平均约低 0.482%，但原完整性状态为 PASS，CRC、序号间断、丢失序号和目标模块缺失均为零。因此它继续计入主性能统计，同时附加时间诊断说明。

| PC 完成时间区间 / s | 有效 MUL1 数 |
|---|---:|
| [10, 15) | 999 |
| [15, 20) | 1001 |
| [20, 25) | 1001 |
| [25, 30) | 1000 |
| [30, 35) | 1001 |
| [35, 40) | 972 |

最后一秒 [39,40) 只有 171 包；这条记录没有主窗口 40 s 之后的完整包。主窗口有效序号 1830121–1836094 连续。

- packet_log.csv 第 7984–7985 行：序号 1836089→1836090，桥端 host_ms 从 14612111 变为 14612234，相隔 **123 ms**；两包在 PC 上共享 elapsed_s=39.9766093。M0、M1、M3 的内帧序号分别为 60418→60419、35001→35002、57723→57724，均连续。其余主窗口桥端间隔为 3–6 ms。
- 第 7948–7949 行：序号 1836053→1836054，PC 完成时间从 39.6493653 到 39.9507388，相隔 **301.3735 ms**，而这两个包的桥端时间仅相隔 5 ms。主窗口中 989 对相邻包共享 PC 完成时间，说明存在批量到达或批量处理。
- 原 summary 还记录文件末尾 **1020 B** 截止片段，故 full_run 为 CHECK；该片段并非完整包，不能直接换算为额外已丢物理扫描。主窗口 PASS 和 5974 包的统计保持原值。

host_ms 来自 Teensy four_module.ino 的 enqueueMultiPacket，在构造 MUL1 偏移 16 时写入 millis()（当前源码第 391 行），代表桥端入队时间，分辨率为毫秒。它不是 STM32 的物理扫描时间，也不是 USB 总线事务时间。PC 的 elapsed_s 则是包完成观察时间；同一读取块中的多个包可具有相同时间戳。

可确认：末段出现桥端打包长间隔，同时 PC 观察到明显缓冲/调度波动。不能仅据这些字段断定停顿由 SPI 饱和、USB 背压、操作系统调度或其他环节引起，也不能把相对于 200 Hz 的计数差直接说成丢失了若干 MUL1 或物理扫描。长间隔确实存在于桥端时间，因此也不能全部归为 PC 时间戳量化误差。

## M012 Repeat 1：完整性异常与时间波动分开记录

主窗口 6002 个候选、6001 个有效包，outer CRC 错误 1 次、有效序列间断 1 次、未解析成功的序号数 2；内部未归属 raw 为 2148 B，另有尾部 1 B。elapsed_s=19.4723392 附近，日志第 3888 行候选序号 1675977 CRC 不通过，前后有效序号为 1675976 和 1675979。具体 raw 恢复证据见独立审计，不把运行时 lost_frames=2 等同于两个原始包均已丢失。

这一记录的 PC 最大完成间隔为 133.2063 ms，对应相邻桥端间隔仅 5 ms。时间波动不能取消已经观察到的 CRC 错误；也不能因为其平均包率仍约 200 Hz 就把记录改成 PASS。

## 复现与追溯

运行本目录 audit_timing.py，仅读取索引指定的原 summary、packet_log 和 module_log，输出 timing_audit.json。脚本接受搬迁前或搬迁后的唯一当前位置，不写原始文件。JSON 包含逐条 5 s 分箱、首末序号与时间、最大 PC/桥端间隔、桥端间隔处的模块序号、日志 SHA256 和性能纳入标记。分箱采用半开区间；其他记录在 40 s 后、实际截止前收到的主窗口完整包另列，避免漏计截止超时部分。
