# MAX11633 内部时钟 FIFO-DMA 完整 FSR 刷新率实验 — 2026-08-28

## 目的

在不改动稳定 Combined 固件的前提下，测试以下采集序列：

```text
0xF8 单字节自动扫描命令
→ 可配置 0 us 起的命令—读取间隔
→ 32 B SPI1 DMA FIFO 读取
```

重点是找出双 FSR 都完成 16 × 16 更新、帧连续且原始数据质量仍通过时的
最高完整刷新率。`0 us` 档是用户提出的“下一次 SCLK 立即读取”实验，不预先
假定其符合 EOC 完成条件。

## 新增内容

- STM32 隔离 profile：`internal_fifo_dma`；
- MAX11633 setup `0x64`：内部转换时钟、外部 3.3 V reference；
- 10 MHz SPI1 仅用于 32 B FIFO 数据读取；
- STM32 160 MHz，双 FSR 每个输出循环完整更新，ACC 降为 1 Hz；
- Module 1 可选 Teensy 桥接，复用已验证的 1188 B ESK1/Host SPI/USB 链；
- 自动 gap 扫描、200 帧质量窗口分析和最佳档回烧；
- 烧录使用项目中已验证成功的最高 SWD 频率 `1 MHz`；
- 独立构建目录与稳定版回滚命令。

## 验证状态

- STM32 `gap=0 us, MUX=0 us` Release 构建：通过；
- Teensy Module 1 桥接构建：通过；
- 原 `safe2p5` profile 回归构建：通过；
- 烧录脚本已按用户要求改为项目中成功使用过的最高 SWD 速度 `1 MHz`；
- Module 1 STM32 已通过 DAPLink 实物烧录；Teensy 桥接已上传到 COM9；
- Host SPI/USB 在全部测试点均保持连续，未发现协议解析、CRC 或帧序号错误；
- 已完成 `0–80 us` 粗扫、`25–40 us` 细扫和 `36/37/38 us` 的 1 us 边界扫。

## 实物结果

| 命令到 FIFO 读取间隔 | USB 实测输出 | STM32 完整双 FSR 扫描 | 无载荷原始码判断 |
| ---: | ---: | ---: | :--- |
| 0 us | 595.421 Hz | 646.831 Hz | 出现约 3840 异常高码，读取过早 |
| 20 us | 419.546 Hz | 457.457 Hz | 出现约 3840 异常高码，读取过早 |
| 35 us | 357.224 Hz | 375.094 Hz | 出现约 3840 异常高码，读取过早 |
| 36 us | 353.236 Hz | 370.645 Hz | 出现 3840/3841，读取过早 |
| **37 us** | **349.165 Hz** | **366.300 Hz** | 未出现 `>=3072` 的早读特征 |
| 38 us | 345.302 Hz | 361.925 Hz | 未出现 `>=3072` 的早读特征 |
| 40 us | 338.141 Hz | 353.732 Hz | 未出现 `>=3072` 的早读特征 |

`37 us` 又进行了 30 s 长测，共收到 10,475 个完整双 FSR 帧：解析错误 0、
序号错误 0，STM32 记录的扫描周期中位数为 2,730 us，即 366.300 Hz。
随后 15 s 诊断采集仍保持 349.332 Hz USB 输出和 366.300 Hz 核心扫描率，
两层均未出现 `>=1024` 的样本。

因此，当前 Module 1 在无载荷数字验证下的最快可信配置为：内部转换时钟、
10 MHz FIFO 读取时钟、`37 us` 命令—读取间隔、`0 us` 额外 MUX 等待；完整
双 FSR 刷新率为 **366.300 Hz**。硬件当前保留此配置。

## 判定

每个 gap 同时检查：完整双 FSR 状态、16 个 MUX 地址、帧序号、协议/CRC、
原始码范围及高码频率。采集器保留原有 200 帧静态质量门作为参考，但它不再
自动决定最快点：无载荷时大量合法的 0 会使边界码比例失败，而读取过早产生的
随机变化反而可能错误通过旧门。自动扫点现以链路有效且不存在 `>=3072` 的
早读特征选择最快候选点。

该结论是无载荷条件下的数字时序上限，不等同于最终传感性能上限。还需在受控
按压下验证响应幅度、相邻单元串扰、两层一致性和重复性；通过后才可将 37 us
并入稳定 Combined 固件。

## 稳定 EOC 策略的 MUX 等待时间扫点

本节与上面的“命令—FIFO 固定间隔”实验分开。这里保留稳定 Combined 的完整
采集逻辑：MAX11633 内部时钟、`0xF8` 自动扫描命令、两个 EOC 完成判定、10 MHz
FIFO DMA 读取，以及下一行 MUX settling 与当前 FIFO 读取的重叠；只把原来的
`FSR_MUX_SETTLE_US=100` 做编译期扫描。

Module 1、Teensy COM9、每点 8 s 无载荷采集结果如下。`EOC_QUALIFIED` 是本实验
的有效性判据；`result=FAIL` 仅表示旧的 200 帧静态质量门被无载荷的边界零值触发，
不表示 EOC、协议或传输失败。

| MUX 等待 | EOC/传输状态 | 解析/序号错误 | USB 实测输出 | 完整双 FSR 扫描 | FSR1 原始范围 | FSR2 原始范围 |
| ---: | :---: | ---: | ---: | ---: | ---: | ---: |
| 100 us | EOC_QUALIFIED | 0 / 0 | 239.410 Hz | 269.760 Hz | 0..694 | 0..614 |
| 75 us | EOC_QUALIFIED | 0 / 0 | 241.435 Hz | 272.331 Hz | 0..692 | 0..496 |
| 50 us | EOC_QUALIFIED | 0 / 0 | 242.940 Hz | 274.123 Hz | 0..690 | 0..593 |
| 25 us | EOC_QUALIFIED | 0 / 0 | 244.249 Hz | 275.938 Hz | 0..702 | 0..587 |
| 10 us | EOC_QUALIFIED | 0 / 0 | 244.875 Hz | 276.702 Hz | 0..696 | 0..544 |
| **0 us** | **EOC_QUALIFIED** | **0 / 0** | **245.872 Hz** | **277.932 Hz** | **0..699** | **0..579** |

相对于 `100 us`，`0 us` 将显式 MUX 等待缩短 `100 us`，测得完整双 FSR 扫描由
`269.760 Hz` 提升到 `277.932 Hz`，提升约 `3.03%`；USB 输出由 `239.410 Hz`
提升到 `245.872 Hz`，提升约 `2.70%`。由于当前代码把下一行 settling 与当前行
FIFO 读取重叠，实际单帧周期只缩短约 `109 us`，不会获得完整的 `16 × 100 us`
收益。

结论分两层：

1. 在本次 Module 1 无载荷数字测试中，稳定 EOC 读出链路的最短已测点为 `0 us`，
   没有早读高码、协议解析错误或帧序号错误。
2. 这不能单独证明模拟 MUX 已充分稳定。最终缩短值还必须在逐行/逐列满压力、
   快速换行和相邻单元串扰条件下比较幅度、残留、重复性和两层一致性。因此稳定
   默认值仍保留 `100 us`；`0 us` 只作为后续受控压力实验的候选下限。
