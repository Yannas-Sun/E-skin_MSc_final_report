# 四模块评估计划：数据、供电、校准与可扩展性

英文原文：[PROGRESS_UPDATE.md](./PROGRESS_UPDATE.md)

日期：2026-08-15

状态：仅完成设计，尚未执行多模块硬件测试。

## 1. 目的与现实基线

本计划评估一个 Teensy 4.1 通过一条共享 Host SPI 总线和一个外部稳压电源，控制最多四个基于 STM32 的 E-SKIN 模块。

这是 planning report 中“五模块目标”的实际四模块验证阶段。本实验不得在没有对每个模块的实际速率和有效模拟数据进行测量的情况下，声称四模块达到 700 Hz。

当前证据分为三种情况：

| 路径 | 单模块实测结果 | 在本计划中的用途 |
|---|---:|---|
| 正常 STM32 Combined | 238.475 个完整新鲜扫描/s | 主要数据基线 |
| SCLK33 `refint7p5` | 439.299 个完整扫描/s | 诊断用途，ADC 时钟超规格 |
| 原版 Teensy 直控 | 700.210 帧/s | 历史对照，绕过 STM32/Host SPI |

因此，多模块生产测试从 100 Hz 开始，以 150 Hz 作为第一个候选点，以 200 Hz 作为压力测试点。最终验收结果采用每个模块的实际测量速率，而不是请求速率。

当前每个 ESK1 帧为 1188 字节，包括 1024 字节的两个 FSR 矩阵、144 字节的九个 ACC 记录、16 字节帧头和 4 字节 trailer。

```text
每秒总线比特数 = 1188 × 8 × 所有模块实测帧率之和
SPI占用率 = 每秒总线比特数 / Host SPI频率
```

在 Host SPI = 10 MHz 时：

| 配置 | 原始数据率 | 约占总线 |
|---|---:|---:|
| 1 个模块 × 238.475 Hz | 2.266 Mbps | 22.7% |
| 1 个模块 × 439.299 Hz | 4.175 Mbps | 41.8% |
| 4 个模块 × 238.475 Hz | 9.066 Mbps | 90.7% |
| 4 个模块 × 439.299 Hz | 16.700 Mbps | 167.0%，不可能 |

因此，四模块测试必须寻找能够适配实际总线的最高公平速率，而不能直接假设历史上的 700 Hz。

## 2. 三个评估核心

评估由三个独立部分组成：

```text
数据容量与数据质量
          ↓
供电与热稳定性
          ↓
校准与重复性
          ↓
1 到 4 模块的可扩展性结论
          ↓
实际边界与五模块推算
```

### A. 数据评估

数据评估包含两个独立的通过条件：

1. 传输正确性；
2. 传感器数据正确性。

传输正确性包括字节数量、模块身份、序号和 CRC。传感器正确性包括 FSR 数据是否新鲜、是否出现冻结或代码坍缩，以及 ACC 是否返回有效且新鲜的数据。

当前周期性 CRC 模式可以用于吞吐率测试，但最终验收必须使用逐帧 CRC 的诊断版本。CRC 正确本身不能证明 ADC 数据有效。

对每个模块、每个不重叠的 200 帧 FSR 窗口，记录：

```text
边界代码比例                    < 65%，两个 FSR 层都必须满足
每个单元 unique value 中位数    >= 4
冻结单元比例                    <= 5%
unique value 不超过 3 的单元    <= 20%
发生变化的单元比例              >= 40%
```

每个模块还要记录：

- 实际帧率和帧间隔 p95；
- 丢帧、序号间隙、Magic 错误、Header 错误和 CRC 错误；
- 内层 CRC 和外层 CRC；
- ACC `WHO_AM_I`、在线掩码和真正的新样本率；
- Teensy 队列最高水位和 PC 写入丢失；
- 公平性：`最小模块帧率 / 平均模块帧率`。

名义多模块通过目标：丢帧率 `<1%`、p95 帧间隔小于请求周期的 1.5 倍、公平性 `>=0.90`、队列不能持续增长，以及全帧诊断 CRC 测试中错误为 0。

### B. 供电评估

供电评估独立于数据评估。如果系统虽然能够传输数据，但出现电压下降、复位或非线性负载增加，也不能算通过。

当前供电要求：

- 使用文档规定的模块输入端 `FPGA_3V3_IN`；施加电压前确认具体 PCB 版本；
- 使用限流稳压电源；
- 使用星形供电；
- 每个模块设置保险丝或电流监测；
- Teensy 和 DAPLink 不得反向给模块供电。

对 1、2、3、4 个模块分别测量：

- 空载电流和待机电流；
- 浪涌电流；
- 100、150、200 Hz 以及实际数据边界下的电流；
- 无接触、均匀压力和动态按压/释放时的电流；
- 分支电压、连接器处电压、电源轨压降、纹波和温度；
- 预热 5 分钟后的电流和每次 10 分钟运行中的变化。

供电通过条件：

- 不发生 brownout、复位或限流；
- 每个模块的电源轨保持在标称值的 ±5% 以内；
- 四模块最坏情况下仍至少保留 20% 电源余量；
- 不出现异常发热或持续热失控；
- 总电流和分支电流能够随着模块数增加而进行合理预测。

需要拟合电流随模块数变化的斜率、截距、拟合残差，以及是否出现非线性电流突增。

### C. 校准与重复性

校准必须按模块分别进行，而不是使用一个全局校准表。

每份校准记录必须包含：

```text
module_id
board serial
CS/IRQ slot
firmware hash
raw zero capture
reference-load capture
timestamp
operator/setup metadata
```

校准流程：

1. 对每个模块进行无压力 zero capture；
2. 在相同物理位置施加相同参考负载；
3. 释放负载并重复采集，以评估滞回和重复性；
4. 比较模块之间的归一化响应；
5. 拆卸并重新装配三次；
6. 每次重新装配后重复 zero/reference 测试；
7. 将共同按压/释放事件与 ACC 时间戳对齐。

校准不能掩盖原始数据质量问题。必须分别保存原始数据、校准后数据、校准参数以及校准元数据。

继承 planning report 的目标：

- 多次校准之间的变化 `<10%`；
- 校准后模块间变化 `<10%`；
- 重新装配后的力学性能保持在基线的 20% 范围内；
- FSR 与 ACC 的剩余时间误差中位数 `<5 ms`；
- 不存在系统性时间漂移。

## 3. 共享总线架构

连接方式：

```text
Teensy SCK/MOSI/MISO  -> 所有模块
Teensy CS0            -> Module 0
Teensy CS1            -> Module 1
Teensy CS2            -> Module 2
Teensy CS3            -> Module 3

Module 0 IRQ          -> Teensy IRQ0
Module 1 IRQ          -> Teensy IRQ1
Module 2 IRQ          -> Teensy IRQ2
Module 3 IRQ          -> Teensy IRQ3
```

### J1 到 Teensy 的连接分配

| 模块 | J1-4 HOST_SCK | J1-5 HOST_MOSI | J1-6 HOST_MISO | J1-7 HOST_nCS | J1-8 HOST_IRQ |
|---|---|---|---|---|---|
| Module 0 | Teensy Pin 13 | Pin 11 | Pin 12 | Pin 10 | Pin 2 |
| Module 1 | Teensy Pin 13 | Pin 11 | Pin 12 | Pin 14 | Pin 3 |
| Module 2 | Teensy Pin 13 | Pin 11 | Pin 12 | Pin 15 | Pin 4 |
| Module 3 | Teensy Pin 13 | Pin 11 | Pin 12 | Pin 16 | Pin 5 |

所有模块：

- J1-2、J1-3 接公共 GND；
- J1-1 `FPGA_3V3_IN` 接独立保护的外部 3.3 V；
- 不能由 Teensy 3.3 V 同时给四个模块供电；
- J1-9 `HOST_SYNC` 在当前桥接程序中不连接；
- J1-10 `NRST` 继续连接到各模块的 DAPLink reset；
- 不将 NRST 当作 Teensy 数据 GPIO；
- 模块应逐个烧录和复位。

总线规则：

- 所有 CS 空闲时必须为 HIGH；
- 任意时刻只能有一个 CS 为 LOW；
- 未选中的 STM32 必须释放 MISO 为高阻；
- 四条 IRQ 必须保持独立；
- 使用公共地和星形外部 3.3 V；
- 启用总线前记录电源电压、电流和每个模块的压降。

当前桥接程序只验证了单模块 Pin 10 / Pin 2 映射。Pin 14/15/16 和 Pin 3/4/5 只是 Module 1–3 的设计分配，还没有完成多模块调度和 `MUL1` 封装测试。

### 数据协议

初始阶段保持 STM32 的 1188 字节 `ESK1` payload 不变。在 Teensy 端增加外层 `MUL1`：

```text
module_id
payload_length
global_sequence
module_sequence
ESK1 payload
outer CRC32
```

每个模块内部的 ESK1 序号独立；global sequence 表示多模块交错顺序；module sequence 表示模块自身的连续性；外层 CRC32 检查模块封装后的完整数据。

## 4. 实际测试顺序

### Stage 0：单模块回归

- 以 `MAX_MODULES=1` 构建；
- 验证现有 GUI 和解析器；
- 空载运行 30 秒；
- 受控压力运行 30 秒；
- 记录帧率、全帧 CRC、FSR 质量、ACC 健康状态和供电。

单模块回归不通过时，不得进入多模块测试。

### Stage 1：供电调试

- SPI 断开；
- 确认电源电压和限流；
- 每次只连接一个模块；
- 记录浪涌电流、待机电流和电源轨；
- 四个模块全部供电后运行 10 分钟。

### Stage 2：共享总线电气测试

- 所有 CS 拉 HIGH；
- 确认每个模块的 MISO 都处于高阻；
- 单独选择每个模块；
- 检查 CS 的 setup/hold 时间、第一个和最后一个 SCK 以及 IRQ；
- 逐个增加模块并检查 MISO 争用或错误 IRQ。

逻辑分析仪发现的电气错误，即使短时间 CRC 通过，也必须判为失败。

### Stage 3：身份和协议测试

从每个模块读取一帧，并检查 `MUL1`、Module ID、数据长度、外层 CRC、内层 ESK1 header、模块序号和全局交错序号。

然后复位一个模块，确认其他模块继续工作，并确认故障模块被标记为 offline 或 timeout。

### Stage 4：数据容量扫描

对 N = 1、2、3、4 个模块执行相同目标速率测试：

| 测试点 | 目标 | 时长 | 作用 |
|---|---:|---:|---|
| D1 | 100 Hz/module | 10 分钟 × 3 | 基线 |
| D2 | 150 Hz/module | 10 分钟 × 3 | 第一个名义候选点 |
| D3 | 200 Hz/module | 10 分钟 × 3 | 压力测试候选点 |
| D4 | 每次增加 25 或 50 Hz | 每个点 2 分钟 | 寻找实际边界 |
| D5 | 238.475 Hz | 仅单模块 | 正常 Combined 参考 |
| D6 | 439.299 Hz | 仅单模块 | 标记为超规格诊断点 |

四模块验收不得使用 700 Hz 作为默认通过条件。历史 700 Hz 结果属于原版 Teensy 直控架构，仅作为架构对照。

### Stage 5：长时间数据测试

在选定的四模块名义速率下：

1. 运行十次、每次 10 分钟；
2. 通过后运行三次、每次 50 分钟；
3. 进行一次达到实际边界的 capture/replay；
4. 保存原始二进制、解析后的 CSV/JSON、CRC 覆盖率、队列最高水位、PC CPU/内存和写入丢失。

### Stage 6：功耗扩展测试

在选定数据点下重复测试 1、2、3、4 个模块的总电流和每个模块分支电流，并拟合电流随模块数和速率的关系。四模块名义速率至少重复三次。

### Stage 7：校准和重新装配

执行每模块 zero、参考负载、释放测试、三次拆卸/重新装配、重新校准以及 FSR/ACC 时间同步测试。

如果只是在校准后通过，而原始数据质量失败，则整体仍判定为失败。

### Stage 8：故障隔离

每次只注入一种故障：移除一个模块电源、复位一个 STM32、断开一个 IRQ、将一个 CS 保持 HIGH、断开一个 MISO，或制造 Teensy 队列压力。

通过条件是：其他模块继续工作；故障模块被标记为 offline/timeout；故障模块恢复后无需重启 Teensy；数据不会与其他模块混淆。

## 5. 可扩展性判定

绘制 N = 1、2、3、4 时的：

- 总帧率和每模块帧率；
- 公平性和 SPI 占用率；
- 传输/数据质量错误；
- 总电流和分支电流；
- 电源压降和温度；
- 校准变化和重新装配误差；
- 队列最高水位和 PC CPU 使用率。

系统只有在以下条件下才算可扩展：增加一个模块只需要增加一条配置表、分配一个 CS、分配一个 IRQ 和设置一个 Module ID，而不需要修改协议、GUI、日志、校准和故障处理逻辑。

最终需要区分三种系统边界：

1. **数据受限**：Host SPI 或采集逻辑无法维持请求速率；
2. **供电受限**：电源、电流或温度余量不足；
3. **校准/机械受限**：原始数据正常，但校准或重新装配重复性不够。

最后将 N = 1–4 的测量结果外推到五模块。如果五模块仍要求 700 Hz，则当前 10 MHz Host SPI 不足，需要更快的通信链路、更短或压缩的数据、模块级聚合器或 FPGA。

## 6. 必须完成的软件与交付物

多模块总线测试前，需要实现和测试：

- `teensy/applications/scalablity/` 中的单模块选择测试；
- `MAX_MODULES` 和 CS/IRQ 配置表；
- round-robin 调度、超时处理、offline/rejoin 状态；
- `MUL1` 外层封装和支持模块 ID 的 GUI/解析器；
- 每模块传输、数据质量、功耗测试和校准计数器；
- 全帧 CRC 诊断模式；
- 模块数、模块 ID、FSR 速率和 ACC 速率的命令行配置；
- `MAX_MODULES=1` 回归测试；
- 稳定版本回滚指令。

最终交付物：

- 四模块接线图和外部供电图；
- 模块清单以及固件/构建 hash；
- 逻辑分析仪捕获；
- 原始二进制帧及解析后的 CSV/JSON；
