## 数据与当前结论

主分析使用18条持续USB接收的YAML记录，全部为FULL、配置200 Hz。四种N=1模块、两种N=2组合、两种N=3组合和一种N=4组合，各有ZERO和记录为MAX的加载条件；每个确定条件只有R1。13条旧CSV记录作为阻塞待机对照独立保留，11条待机YAML是旧记录映射，没有重复计入。

新分析入口为 `script/Main/analyze_power_revision.py`，图表入口为 `script/Main/power_revision_figures.py`。派生结果存入 `DATA/reference/analysis_v2_1/`，旧 `DATA/analysis/` 保持原样。

- N=4持续接收：零载支路电流合计72.513 mA，加载78.720 mA，增加6.207 mA（8.56%）。源端输出侧功率估计分别为237.408 mW和257.651 mW。
- 五种多模块零载配置相对单独测得的N=1电流之和，预测误差为−1.434%至−0.524%，分母为预测值。结果是描述性核验，不能用共享的单模块参考值构成五次独立重复。
- 新数据最低模块MIN读数为3.224 V，出现在N=3、M0-M1-M2、ZERO的M0支路，相对项目下限3.135 V的差为89 mV。它不是高速瞬态最低电压的保证。
- P-H1改为检验单模块记录对多模块组合需求的预测；P-H2限定到记录的电压读数。主图保留各组合点，零载与加载分开，没有把组合间差异画成同条件重复误差。

## 明确限制与对应未来工作

| 限制 | 目前可以报告 | 对应后续工作 |
|---|---|---|
| 每确定条件只有R1 | 该次配置的读数、描述性组合差异与预测偏差 | 固定接线、加载规程后进行独立重复，估计重复SD及测量不确定性 |
| 仅测试部分组合与N≤4 | 已测四个单模块、两个双模块、两个三模块及四模块结果 | 记录物理模块映射，平衡模块组合和次序；更大规模需独立验证 |
| M0–M3是记录标签，未有设备UID身份链 | 在物理标签跨run保持一致的假设下比较 | 保留模块照片/编号、槽位与每次重接映射，不能只靠槽位自动识别板卡 |
| MAX均写2000 g，但没有面积、位置、层数与分配 | 所记录加载状态下的电气需求 | 从现有笔记和照片补清整套/每模块负载定义，采用可重复的加载方式；未覆盖状态不称绝对最坏工况 |
| 电压和支路电流顺序读取，avg未证实为时间平均 | 代表读数之和、Vs×ΣI输出侧功率估计 | 核对仪表主读数含义与精度，保存同步总电流/模块电压时间序列 |
| 5处主电流读数略超出MIN/MAX，差0.002–0.005 mA | 保留原数值并在qc_issues.csv标记 | 回查照片及显示精度，不擅自裁剪原数据 |
| 日期、开始时间、操作者缺失；30s/10s为预填 | 记录已有条件并显式保留缺项 | 能恢复则补来源；以后记录实际预热、测量窗口、环境和仪表信息 |
| 故障计数0来自模板 | 记录约定，不据此声称无复位/欠压/通信异常 | 配套保存实际事件日志与测量时窗，区分未观察与未监测 |
| 没有同步峰值、浪涌、纹波或切换波形 | DMM读数不代表高速瞬态边界 | **未来工作（用户2026-09-07确认）**：测启动峰值、供电纹波及负载切换波形；本轮不要求补测 |
| 温度没有热平衡或匹配停留时间证据 | 温度观测点 | **未来工作（用户2026-09-07确认）**：记录环境、初温和持续温升曲线，验证热稳态；本轮不要求补测曲线 |
| 没有实际电源板容量与20%余量验证 | 所测配置的输出侧需求；不含Teensy USB输入和稳压器损耗 | 若要给出整机供电规格，另测相关功耗边界、板级容量和热限制，再验证目标余量 |
| 阻塞与持续接收来自不同记录 | 分组描述性对照 | 若要归因于USB读取状态，固定其余条件并平衡测试次序进行配对复测 |

以上未来工作不表示需要因DELTA协议更新重做当前FULL功耗实验。动态供电和20%余量测试仍属于此前暂缓的验证任务。

“故障监测记录不完整”指的是证据来源和观察窗口未充分记录：旧记录中reset、current_limit、brownout、data_stop和data_gap等计数部分沿用模板的0，未附对应监测方式、日志或经核实的观察时长。这个缺口不能用来判断是否发生过故障，也不影响已有电压/电流读数的保存。应区分“实际监测且未观察到”“未监测”和“有记录的事件”；只有能恢复的真实观察才补记来源，未知项不推定为0。人工看到GUI持续刷新，只支持该观察窗口内未见明显停止，不能据此推定无短时欠压、复位或丢帧。M0 connector接触不良另有用户确认的事件记录。
